# Draft curriculum completion and microSD integration candidate

## Completion contract
CPL1 records are 96 bytes: magic/version (4), contiguous sequence u32 LE, zero-padded stable lesson ID (80), lesson revision u32 LE, CRC32 LE. One event per first preview completion of a lesson revision. A revision remains an independent historical reference even when not currently installed. Completion means reaching the end of a draft activity sequence, not accuracy, mastery, a certificate or grade promotion. No real student identifiers, answers, audio, ink or credentials in this candidate.

Backend: exclusive owner, exact file length, exact fixed-slot reads, append at expected record count with durable commit and no truncation/overwrite. Replay validates CRC, canonical IDs, sequence and uniqueness; malformed or partial tails fail closed and remain intact. Duplicate completion is idempotent. Return Saved only after exact readback and new length check; ambiguous write requires replay. Bounded 256-record index is an engineering preview limit, not the long-term curriculum limit. CRC detects accidental corruption, not adversarial changes or missing complete tail. Production needs authenticated identity, verified high-water metadata, encrypted at-rest evidence, independent backups and recovery, larger indexed storage and actual power-loss testing.

## Physical SD qualification
M5Stack's [Tab5 microSD example](https://docs.m5stack.com/en/arduino/m5tab5/microsd) documents SPI GPIO CS 42, SCK 43, MOSI 44, MISO 39, FAT32 example and board package >=3.2.2. Current pinned Arduino 3.2.1 may differ. Isolated `sd_capacity_probe` is compile-only until accepted; uses documented pins, 4 MHz candidate, SD.begin explicit format=false, measures capacity/filesystem sizes and unmounts. No application file reads/writes or directory enumeration; mounting does not guarantee block-device read-only access. Back up the removable card independently before running; never format or repartition automatically. If mount fails, inspect actual filesystem and pinned SDK support first. No firmware changes to normal learner, no automatic mounting, no fallback to default NVS.

Next gates: compile on exact pinned SDK; guarded temporary app-only install with fresh dual full flash backup and separate card backup; detect reported 512 GB card; confirm no format; restore known learner app and verify battery/math; then dedicated synthetic append/reboot/power-loss/readback/removal test on approved scratch card or reserved namespace. Only wire CompletionLedger to learner when durable SD backend, recovery, capacity, identity and backup are validated. Reuse existing curriculum resume checkpoint separately; ensure interrupted completion and checkpoint operations reconcile safely. Do not store grades or actual child data until all security and privacy gates pass.

## Durable regular-file reference and guarded probe installer
Added CompletionFile POSIX reference adapter over a caller-owned exclusive regular O_RDWR|O_APPEND descriptor. Exact size and bounded record reads; single append, fsync and length check; ledger exact readback. No path creation, truncation, retry after partial write, or automatic repair. Host real-file test covers reopen/replay, duplicate, torn tail refusal, incorrect descriptor modes. fsync success on host is not SD power-loss certification; file creation directory durability, ESP VFS fcntl/lseek/fsync support, complete-tail loss, high-water metadata and card identity remain gates. No learner integration.
Guarded installer accepts -SdCapacityProbe -CardBackupConfirmed (operator attestation, not card-backup verification), mutually exclusive with other probes; requires matching dual full-flash backups and existing revision/image/device/live-table checks. No SD format. Use preflight first, then explicit -Install after independent card backup. Record screen capacity, filesystem bytes, used bytes, then restore exact prior learner app from current verified flash backup. No restoration or flash performed by repository changes.
