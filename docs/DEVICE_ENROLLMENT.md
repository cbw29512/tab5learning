# Test device enrollment and mutual authentication

## State and data
- Existing planned assignment remains PLANNED.
- Test-only credential record: normalized device_id (unique, must have a planned assignment), random 32-byte shared secret, created_at UTC, actor (authorized admin), state KEY_PENDING. The local test database is outside Git, never returned to browser or logs. No default/shared device key. Duplicate enrollment is rejected; no implicit replacement.
- Host authentication attempt: device_id, host nonce (32 random bytes), start monotonic time, consumed flag. Ephemeral, 10-second lifetime. Device nonce independently generated by device. No persistent session or authorization granted by this host-only reference.
- Transcript: ASCII versioned domain "TAB5-AUTH-V1" followed by NUL, role ("device" or "host"), NUL, normalized ASCII device_id, NUL, raw 32-byte host nonce, raw 32-byte device nonce. HMAC-SHA256 with per-device secret. Proofs compared in constant time. Different roles prevent reflection. Host attempt consumed on first completion including invalid proof; expired attempts rejected. Firmware must independently verify host proof and consume its own challenge before allowing any authorized operation.
- Enrollment UI only prepares a credential; it does NOT load it onto a device or authenticate it. No serial changes. Key injection will require explicit trusted maintenance action, verified physical hardware identity, protected local transport and no secrets in repository/artifacts/logs. Flash encryption/secure boot and Windows storage ACLs remain release gates. SQLite secret storage in this slice is synthetic test use only; not production secure storage.
- Future KEY_PENDING -> ENROLLED only after key installation plus verified mutual handshake. No action in this slice transitions to ENROLLED or PROVISIONED. Assignment sync additionally requires authenticated operation, durable acknowledgement and replay protection.

## Acceptance
Test-mode administrator can prepare one credential for an existing planned device. Non-admin and normal mode denied; duplicate and unknown devices rejected; UI displays KEY_PENDING without exposing key. Test reference challenge with fresh nonces, wrong key/device/role, tampering, timeout and replay. No firmware reflash required for this slice. Next: physical key installation and firmware-side matching reference; do not send actual student data until security gates pass.
