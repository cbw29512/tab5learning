# Teacher Studio authentication — host prototype

Accounts: unique normalized username, role (teacher/admin), random password salt, scrypt hash, enabled flag, failed attempt count, lockout expiration. No plaintext passwords. First admin created only in empty account database, through local setup. Subsequent account creation requires an authenticated administrator. Sessions are process-local random tokens with expiration; role and enabled status rechecked on each privileged operation. No default credentials. Database and backups must remain outside GitHub. Local OS permissions, encryption at rest, per-student authorization, recovery, persistent rate limits across clock changes and authenticated USB are separate release gates. No claim of protection against a hostile Windows administrator. Tests use synthetic credentials only.
