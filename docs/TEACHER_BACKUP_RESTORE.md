# Teacher Studio independent backup and recovery — required beta gate

## Objective
Teacher can protect both a child's full learning history and the teacher's own reusable instructional work on the Windows computer, independently of the Tab5 and its 512 GB microSD. No cloud or wireless requirement. A failed or replaced card/device must not destroy the only copy of either category.

## Two independent archives
- Student archive: authorized student/device identity, immutable attempts, original handwriting/audio/camera evidence, assessments, corrections, assignments, progress, achievements/certificates, preferences and exact referenced curriculum/deck versions. Derived mastery can be rebuilt; never substitute a summary for original evidence. Include unfinished drafts only when supported and clearly marked.
- Teacher content archive: author/owner identity, versioned flashcard decks, custom lessons, media, attribution/licenses, skills/grade metadata, answer keys and assignment templates. No student responses, grades, recordings, identifiers or device credentials in a reusable content export. Preserve older referenced versions. Shared content is scoped by existing permissions.
- Separate optional complete workspace backup contains both categories and their dependency links; access requires authorization for every included record. Do not export passwords, session tokens, device keys or recovery secrets in ordinary content/student backups. Separate approved credential recovery process.
- Purchased curriculum recovery must respect package signatures and future entitlement policy; never treat a content export as a license to redistribute it.

## Manifest and lifecycle
Manifest: schema version, archive ID, kind, authorized owner/scope, creation sequence/time and clock quality, source identity (student archives only), content/version references, record counts, entry sizes and integrity hashes, encryption format/version, verification result. Bounded parsing and streaming; no arbitrary paths, traversal, code execution or trust in imported metadata.
States: requested -> authorized -> staged -> validated -> encrypted and durably committed -> independently read back -> available. Failed/incomplete backups never replace a verified archive. Restore: select -> authenticate -> validate archive and dependencies -> preview target/differences -> explicit approval -> staged import -> verify -> commit -> audit. Resume/retry idempotently; conflicting IDs or histories require review. Do not silently roll back newer student progress or overwrite teachers' work. Keep original archives intact until authorized retention/deletion applies.

## Teacher Studio UX
Show Backup & Restore on the authenticated dashboard. Separate actions: Back up student progress (select authorized student; connect device over authenticated USB for fresh data), Back up my teaching materials (works without Tab5), Restore student progress (identity and newer-history checks), Restore teaching materials (merge identical versions, review conflicts), View backup history. Show last verified backup, scope, date, size, and explicit stale/incomplete/error state. A local export or saved database is not necessarily an independently verified backup. Let authorized users choose an independent destination; do not silently upload. Suggest backing up during USB sync and before updates, and after content edits; exact automated cadence and retention limits require validation. Encrypt sensitive archives at rest with a recoverable authorized key process; test restore on a replacement computer and device, not just the original Windows account.

## Device-side recovery
Use verified, versioned microSD snapshots and integrity checks after physical validation. Internal firmware/boot recovery and teacher-held independent archives must remain distinct. Preserve the original data after corruption; no automatic factory reset, downgrade, formatting or blind restore. If card or firmware is unavailable, authorized recovery uses independent host backup and validated USB/bootloader path. No new charger, partition or filesystem changes authorized here.

## Acceptance
Synthetic data only until privacy/security gates pass. Test independent teacher content backup with no device, student archive with all evidence and version dependencies, wrong teacher/student, tampering/truncation, interrupted writes, full disk, loss of microSD, replacement computer/device, exact retry, stale/conflicting history, missing dependencies, key recovery and authorized deletion/retention. Restore must reproduce original records and versions, not just counts. Verify archive integrity and actual restore separately; show errors without logging private content. No real student records until these gates pass.

## First implementation slice
Synthetic-only owner-scoped text flashcard archive codec (PLTA v1, bounded JSON, SHA-256 integrity not authentication), consistent SQLite snapshot including every immutable version, nonmutating preview, explicit transactional restore with identity/conflict checks and readback. Exact retries and older matching archives do not remove newer versions. No student tables accessed; username matching is not production identity proof. Not yet encrypted, written to an independent destination, wired to UI or usable with real records. Assets, lessons, student archive, authenticated USB, key recovery and physical recovery remain open.

## Independent file persistence slice
Synthetic-only local service selects an existing directory outside the workspace, exports a bounded versioned text-deck archive, stages in the destination directory, flushes and verifies exact bytes, publishes to a unique no-overwrite filename, then verifies published bytes. POSIX hard-link publication and directory sync require filesystem support; Windows uses non-replacing rename, file flush and readback, not a demonstrated power-loss guarantee. Receipt includes SHA-256, length and version count. Restore preview returns the exact file digest and restore checks it before applying the same bytes transactionally. No arbitrary filesystem path through web routes, no device access, no encryption or production identity proof. Separate directory alone does not guarantee a separate physical drive; use an independent medium during acceptance. Browser controls, Windows filesystem validation, portable encrypted keys, student records and full asset archives remain open.

## Teacher Studio synthetic backup center
Run `python -m tools.run_teacher_web --test --backup-dir <existing independent folder>` to enable the authenticated dashboard Backup & Restore page. Local operator configures root; browser supplies only a generated archive basename. Per-account subfolders, bounded listing, validation, save receipt and session-bound digest proof for explicit restore. No cross-account restoration or arbitrary web paths. Test archives remain unencrypted; student backup explicitly unavailable. Destination on a separate physical drive and Windows behavior still require acceptance. No production access or real records.

## Protected portable archive candidate
PLTE v1 = magic/version + 12-byte random nonce + AES-256-GCM ciphertext/tag; authenticated header, validated inner PLTA v1. Separate OS-generated 256-bit recovery key represented as 64 lowercase hexadecimal characters; no account password or Windows DPAPI binding. Key must be retained independently; loss of key means no decryption. No plaintext written by protected file path; existing independent publication and digest-confirmed restore reused. Uses cryptography==50.0.2, documented AESGCM API https://cryptography.io/en/latest/hazmat/primitives/aead/; provider failure must not fall back to plaintext. Synthetic-only, bounded 16 MiB inner archive, no production security certification. Recovery-key UX, protected browser integration, key storage/rotation, Windows and separate-computer validation, and streaming student/media archives remain open. Existing plaintext test UI remains explicitly unencrypted. CI dependency pinned for this candidate; full release dependency locking/review pending.

## Protected dashboard workflow
In configured synthetic backup center, open Encrypted backups. POST generates a fresh key displayed once per response, with a session-bound proof; teacher retains it separately, re-enters twice and acknowledges retention before save. Protected files listed as locked, never claimed verified from filename. Preview requires key, confirmation requires re-entry and session-bound exact ciphertext digest. Key never intentionally persisted, included in restore proof fields, logged or put into URL; no-store response and loopback-only existing controls. Python/browser memory and OS clipboard/cache are not secure erasure guarantees. One generated key per save workflow; replay is non-destructive but can create another archive. Legacy plaintext test path remains explicitly labeled. No student records, production key management or Windows acceptance yet.

## First student archive slice
PLSE v1 protected mathematics history binds canonical anonymous student and device IDs inside an authenticated AES-GCM envelope, using existing replay-validated PLMB evidence. Shared cryptographic and independent file-publication primitives retain existing teaching format. Export latest scoped host archive; preview checks history without mutation; explicit exact-digest restore uses existing transactional append-only archive. No fresh USB read, no real student data, no physical restoration, no replacement-device identity remap, no other subjects or evidence media. Existing host snapshot may be stale and cannot be labeled a full device backup. Tests cover wrong key/identity/scope, divergent history, changed file and preservation of newer history. CI pending.
